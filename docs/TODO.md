## 第一阶段：P0 核心闭环与第一版阻断项

### P0-01 数据源配置与连接检查

- [x] **已完成｜P0**：完善演示数据源配置和连接状态验证。（2026-09-08）
  - 现有基础：支持内存 SQLite；已有 Trino 客户端和配置项；提供 `/health` 接口。
  - 剩余工作：
    - 健康检查实际连接数据库并执行轻量只读探测。
    - 区分配置错误、网络错误、认证错误和查询引擎错误。
    - 验证或明确记录数据库账号的只读属性。
    - 错误响应不得暴露密码、令牌或完整连接串。
  - 验收标准：正确配置返回连接成功；错误配置返回可理解且已脱敏的失败原因。
  - 完成证据：SQLite 与 Trino 均执行真实 `SELECT 1` 探测；SQLite 通过 `query_only` 和 authorizer 强制只读；Trino 必须显式声明只读；`/health` 在连接失败、配置无效或非只读时返回脱敏的 503；健康响应字段使用安全白名单；相关自动化测试和完整回归均通过。

### P0-04 SQL 基础安全校验与后续选型（AST 暂缓）

- [ ] **部分满足｜P0-阻断（基础边界）**：维持 SQL 基础检查与受限执行路径，补齐可验收的访问约束；完整结构化校验另行选型。
  - 现有基础：检查单条 `SELECT`、来源表、强制过滤条件、时间范围和 `LIMIT`。
  - 本版工作：
    - 保留现有检查并补回归，保持受支持计划到确定性 SQL 的路径，不开放模型任意 SQL 执行。
    - 接入可信身份、角色与授权对象检查，配合数据库只读权限和资源限制。
    - 记录现有字符串检查不能覆盖的结构/语义风险，拒绝没有可验证安全边界的查询。
  - 暂缓待办（不作为 v1.1.0 AST 发布门槛）：Parser/AST、CTE/子查询/JOIN 全对象检查、通用危险函数及结构绕过识别；不删除这些风险，也不标记完成。
  - 技术选型：尚未确定；不预设 SQLGlot，不擅自引入替代库。后续另行评估体积、开销、维护和方言/规则覆盖。
  - 本版验收：受支持查询正常，原有拒绝用例不退化，授权失败不进入执行器，只读限制有目标引擎证据；未覆盖复杂结构明确披露，不宣称已实现全面 SQL 语义验证。
