## 行为变化

改造前：校验失败 → 增加重试计数 → 原样 SQL 生成；没有下一轮模型反馈调用。

改造后：校验/执行失败 → 有界反馈快照 → 判断可恢复性和一次修复预算 → 携带反馈的结构化模型调用 → 保护原约束并检查有效变化 → 时间/计划/SQL/结果重验，或明确停止。

反馈包含轮次、失败阶段、错误、上一轮计划/模型提案/SQL 和结果行数，不发送原始结果行。新错误反馈会去除常见凭据字段、Authorization/Proxy-Authorization、Bearer 和 URL；限制错误文本、快照和请求长度。现有全项目日志脱敏仍是 M5 的独立工作，不能据此宣称全部旧日志已经安全。

## 当前支持范围

- 无效指标 ID：仅当有一个权威知识候选时允许修正，不允许修改指标定义。
- 重复列错误：仅当计划确有相同重复分组时允许去重，不允许删除分组要求。
- 其他错误保留证据并停止：空结果、权限拒绝、缺表/数据、连接故障、生成器程序错误、SQL 校验失败等。
- 模型 STOP、超时、结构非法、删除筛选、变更日期/指标、无有效计划或 SQL 变化均停止。
- `max_retries=0` 不调用修复模型；配置为 2 或更大也最多一次修复。没有新增传输自动重试。

这是有边界的反馈消费能力，不是 M2 完整需求绑定，也不是 M6 独立复核或任意 SQL 自动修复。

## 主要改动

| 文件 | 职责 |
|---|---|
| `agent/nodes/feedback_repair.py` | 反馈快照、可恢复性、结构化模型调用、约束保护与停止原因 |
| `agent/nodes/llm_planner.py` | 复用权威知识映射；固定本次请求参考日期 |
| `agent/graph.py` | 两套工作流共用修复节点，修订后重验而非直接执行 |
| `agent/nodes/validator.py` | 计划失败提供结构化反馈 |
| `agent/nodes/sql_generator.py` | 生成器异常转明确终止，避免重复运行缺陷 |
| `agent/state.py` | 反馈历史、实际修复请求/响应和结果字段 |
| `tests/test_feedback_loop.py` | 两套工作流、真实 SQLite 结果及外部故障/模型契约测试 |
| `tests/test_workflow.py` | 更新空数据不再原样重试的预期 |
| `tests/test_feedback_live.py` | 默认跳过的真实模型验收，显式授权后才启用 |

反馈可在 `retry_decision` 阶段 trace 的 produced/state_after 中查看。首次规划 payload 不携带其他请求历史；当前公开 API 不增加反馈字段。
