# AI 意图驱动问数工作流技术方案

## 技术方案概述

在现有 LangGraph/ScoredWorkflow 前端增加 AI 意图识别、意图校验、结构化检索条件构建和知识候选校验。知识库返回 Top N 候选后，现有 LLM 规划器结合原问题、结构化意图和候选知识生成逻辑计划，后续继续使用确定性 SQL 生成、安全校验、执行和结果评分。

完整设计见：`docs/superpowers/specs/2026-08-30-ai-intent-grounded-workflow-design.md`。

## 技术选型

| 类别 | 选择 | 理由 |
|---|---|---|
| 工作流 | LangGraph + ScoredWorkflow 降级实现 | 保持现有运行模式一致 |
| 意图模型 | 复用现有结构化 LLM 客户端 | 首版不增加部署复杂度 |
| 知识检索 | 结构化接口 + 本地加权召回 | 可测试，未来可替换 Qdrant |
| SQL | 确定性规则生成 | 防止模型编造表字段并保持安全 |

## 模块划分

| 模块 | 职责 | 依赖 |
|---|---|---|
| Intent Recognizer | 抽取用户原始意图 | LLM Client |
| Retrievability Validator | 按查询类型判断意图是否具备检索条件 | AgentState |
| Retrieval Query Builder | 生成结构化知识检索条件 | Intent |
| Knowledge Retrieval | 返回 Top N 企业知识 | Knowledge Client |
| Knowledge Validator | 判断候选是否可靠或需要澄清 | Knowledge |
| Grounded Planner | 结合原问题、意图与知识生成计划 | LLM Client |
| SQL/Execution/Result | 生成、校验、执行和评分 | 现有实现 |

## 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 意图识别与知识检索顺序 | 先意图、后检索 | 避免直接用整句关键词匹配导致错误召回 |
| 意图模型是否决定正式指标 | 否 | 正式口径必须来自企业知识库 |
| SQL 是否由模型自由生成 | 否 | 保持确定性和安全边界 |
| 不可检索意图是否自动循环 | 否，生成澄清回答 | 没有用户新信息时重复调用没有增益 |
| SQL 重试范围 | 只重试 SQL 阶段 | 避免重复调用意图与知识检索 |

## 实现计划

1. 以 TDD 增加意图识别、校验与状态契约。
2. 以 TDD 改造结构化 Top N 知识检索接口。
3. 以 TDD 升级 grounded planner 与计划校验。
4. 重连 LangGraph 和 ScoredWorkflow。
5. 扩展追踪与 Debug 验证报告。
6. 运行全量测试并进行代码审查。
