## 维护规则

1. 正在推进且有完成条件的事项放入 `Projects`。
2. 安全、质量、知识治理等持续责任放入 `Areas`。
3. 架构、接口、运行手册等可复用内容放入 `Resources`。
4. 已完成阶段、被替代方案和历史决策放入 `Archives`。
5. 文档只记录密钥配置位置，不记录真实 API Key。
6. 项目能力、数据来源或评分规则发生变化时，同步更新对应文档的“最后更新”日期。
