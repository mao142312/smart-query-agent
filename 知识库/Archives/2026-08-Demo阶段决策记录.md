# 2026-08 Demo 阶段决策记录

- 阶段：首个端到端 Demo
- 归档日期：2026-08-16

## 已确认决策

1. 在正式知识库尚未建立时，用本地 JSON 模拟指标知识，用内存 SQLite 模拟业务数据，以先验证完整链路。
2. 指标口径必须由知识定义驱动，不能针对用户问法在答案代码中写死。
3. 支持从基础指标派生总计、分组明细和占比等查询计划。
4. 每轮 SQL 都必须进行 SQL 规则评分和结果评分，并保存逐轮记录。
5. 最终可信度使用各阶段最低分，避免平均分掩盖严重缺陷。
6. 用户界面必须展示知识检索、语义规划、SQL 校验和结果评分，特别说明评分依据与已知边界。
7. 接入真实 DeepSeek `deepseek-v4-flash`；模型负责理解与表达，确定性规则负责口径、安全和数值约束。
8. API Key 使用本地配置文件承载且不提交；思考模式开启。
9. 前端明确显示当前数据来自 Demo SQLite，避免用户将演示数字当作真实指标。

## 已解决问题

- “总开户数 + 各地区开户数”曾只回答总数，现已支持在一个回答中同时输出总计与分组结果。
- 答案组织曾依赖固定文案，现改为根据语义计划中的投影与基础指标结果生成。
- 可信度只显示百分比但缺少依据，现已增加四阶段证据链、检查项权重和结果评分边界。
- 置信度圆环中的 `100%` 曾垂直偏上，已调整为居中显示。

## 阶段结论

Demo 已证明技术流程可行，但尚不能证明真实业务指标正确。生产可靠性最终依赖正式知识库、真实数据源、权限治理、数据新鲜度、历史基线和权威报表对账。
