# 系统架构与处理流程

- 最后更新：2026-08-30

## 组件边界

```text
React 控制台
    │ POST /v1/ask
FastAPI / AskDataService
    │
ScoredWorkflow
    ├─ KnowledgeClient：当前为本地 JSON Mock，未来接真实知识库
    ├─ LLMClient：DeepSeek V4 Flash，负责规划与表达
    └─ QueryClient：当前为内存 SQLite，未来接 Trino
```

## 请求处理流程

```text
用户问题
  → AI 结构化意图识别
  → 意图可检索性校验 ──不通过→ 请求用户澄清
  → 构建结构化检索条件
  → Top N 知识检索
  → 知识候选可靠性校验 ──不通过→ 请求澄清或拒绝执行
  → Grounded 语义规划（原问题 + 意图 + 候选知识）
  → 计划评分 ──低分→ 拒绝执行
  → SQL 生成
  → SQL 校验 ──低分→ 有限重试
  → SQL 执行
  → 结果评分 ──低分→ 有限重试
  → 数值一致性约束下生成答案
  → 输出答案、综合分数和证据链
```

## API 输出重点

`POST /v1/ask` 返回 `answer`、`confidence`、`status`、`scores`、`validation_report` 和 `llm_used`。当 `debug=true` 时额外返回 `sql`、`score_details`、`sql_history`、`trace` 与 `llm_error`。

`validation_report` 固定包含意图与可检索性、知识检索、语义规划、SQL 校验、结果评分五步；每步包含摘要、实际产出、评分项、权重、得分和问题说明。
